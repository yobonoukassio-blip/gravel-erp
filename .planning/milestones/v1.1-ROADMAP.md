# v1.1 — Polish & Gaps (shipped 2026-05-17)

**Defined:** 2026-05-16 (after v1.0 archive)
**Shipped:** 2026-05-17
**Duration:** ~36h elapsed
**Phases:** 3 (Phase 7, 8, 9)
**Plans:** 6 (2 + 3 + 1)
**Commits:** 67 since v1.0 close

## Goal

Close the v1.0 audit gaps that prevented the dashboards from showing real
numbers and the alert engine from actually notifying anyone. v1.0 had the
data model + ingest plumbing; v1.1 made the loop close: cost rolls up daily,
PM checks fire automatically, alerts route to email/SMS/in-app.

## Phases

### Phase 7: Finance Real (2 plans, shipped 2026-05-16)

**Goal**: Dashboard Finance shows non-zero numbers — cost writers DI in each
producer module, @Cron daily aggregation, UI tiles DSH-03/04/05/06,
`alert_rule` seeded by migration.

**Requirements closed:** FIN-R01..R06

**What shipped:**
- Cost writers wired into Extraction, Transport, Concassage, Criblage,
  Foration, Tir, Maintenance — no more `0n` hardcodes.
- `CostPerTonAggregatorJob` @Cron daily at 04:00 UTC materialising
  `cost_per_ton_daily` per site × calibre.
- Finance Group (DSH-05) consolidated P&L with site/contract/material
  drill-down.
- HSE (DSH-04) tiles: incidents, fréquence, conformité.
- 5+ `alert_rule` rows seeded by migration covering stockpile, spare-part,
  HSE, explosifs, fuel anomaly.

### Phase 8: Operational Alerts Closure (3 plans, shipped 2026-05-17)

**Goal**: Preventive-maintenance and spare-parts alerts fire automatically —
end of operational silence.

**Requirements closed:** ALT-01, ALT-02

**What shipped:**
- Equipment meter denormalization (`hour_meter_current` / `odometer_km_current`
  columns) with event-driven `MeterUpdateHandler` listening to
  `production.fuel.refuel_appended` + `production.transport.rotation_completed`.
- Spare-part threshold event flow with recovery event + dedupe key
  `spare_part:<id>:below_threshold`.
- `PreventiveMaintenanceSchedulerJob` @Cron hourly with tenant fan-out and 3
  interval paths (hours / km / days). Idempotency via
  `WorkOrderService.findOpen()`.
- `WorkOrderService.close()` advances PM plan state (D-04) — closes the cycle
  so the scheduler doesn't re-open the same WO every tick.
- `PmOpenedAlertHandler` rewired to call `AlertsService.createFromEvent` with
  severity mapping `warning→high`, `critical→critical`.
- HSE-04 gate: `WorkOrderService.close()` blocks closure when assigned
  technician lacks valid `FORMATION_HSE` certification.
- 31 tests across 3 spec files (16 + 11 + 4).

### Phase 9: Notification Delivery (1 plan, shipped 2026-05-17)

**Goal**: Alerts reach the right recipients by email and SMS, with retry/backoff
and in-app badge — end of `logger.log()` stubs in `AlertDispatcherService`.

**Requirements closed:** NTF-01, NTF-02, NTF-03

**What shipped:**
- `NotificationModule` with BullMQ queue `notifications`, processor with
  exponential retry (5 attempts × 30s base), dead-letter via failed set.
- Brevo email provider (`@getbrevo/brevo` v5) with graceful degradation:
  missing API key / missing recipient / dry-run all return `skipped`.
- Twilio SMS provider with per-recipient rate limit (3/h via Redis sliding
  window), 4xx → non-retryable.
- In-app `Notification` entity + controller (`GET /api/notifications?unread=true`,
  `PATCH /api/notifications/:id/read`, `PATCH /api/notifications/read-all`)
  with RLS policy.
- `AlertDispatcherService` refactored: replaced 5 `logger.log()` stub paths
  with `NotificationService.dispatch()` enqueues, one job per (user, channel).
- Angular `NotificationBadgeComponent` in app header with 30s poll + dropdown
  + optimistic mark-as-read.
- 8 env vars documented (`BREVO_*`, `TWILIO_*`, `NTF_DRY_RUN`, `REDIS_URL`,
  `AUTH_JWT_SECRET`).
