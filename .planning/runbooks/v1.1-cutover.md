### 4.2 Create Keycloak realm group + roles (D-25)

Realm: `gravel-prod` (single realm for v1.1; per-country realms = Phase 6B / v2).

```bash
# 1. Get admin token
ADMIN_TOKEN=$(curl -s -X POST "$KEYCLOAK_URL/realms/master/protocol/openid-connect/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "client_id=admin-cli&grant_type=password&username=$KC_ADMIN_USER&password=$KC_ADMIN_PASS" \
  | jq -r .access_token)

# 2. Create tenant group
curl -X POST "$KEYCLOAK_URL/admin/realms/gravel-prod/groups" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"{CUSTOMER_CODE}"}'

# 3. Confirm default roles exist on the realm (idempotent)
for ROLE in DIRECTEUR_SITE CHEF_CARRIERE MAINTENANCE_MANAGER GESTIONNAIRE_STOCK OPERATEUR COMPLIANCE_OFFICER; do
  curl -X POST "$KEYCLOAK_URL/admin/realms/gravel-prod/roles" \
    -H "Authorization: Bearer $ADMIN_TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"name\":\"$ROLE\"}" || true   # 409 if already exists — fine
done
```

### 5.3 Bulk user provisioning via Keycloak Admin API (D-25)

Per D-25, user provisioning is automated — no manual user creation.

```bash
pnpm --filter api ts-node scripts/keycloak-bulk-provision.ts \
  --csv ./cutovers/{customer}/users.csv \
  --realm gravel-prod \
  --group {CUSTOMER_CODE} \
  --temp-password-policy oneshot \
  --send-welcome-email true
```

What the script does:
1. For each row in `users.csv`, calls `POST /admin/realms/gravel-prod/users` with a temp password.
2. Assigns the user to the tenant group `{CUSTOMER_CODE}`.
3. Assigns the requested `role_code` from the CSV (one of the 6 default roles).
4. Triggers Keycloak's built-in "Update Password" required action so the user must set a new password on first login.
5. Sends the welcome email (Brevo, via Phase 9 NotificationService) with the login URL + temp password.

```bash
psql $DATABASE_URL -c "SELECT count(*) FROM equipment WHERE tenant_id = '{tenant_uuid}'"
psql $DATABASE_URL -c "SELECT count(*) FROM supplier WHERE tenant_id = '{tenant_uuid}'"
```

Each count must match the row count of the corresponding CSV (excluding header + `#` comment lines).

- ❌ Historical work orders / maintenance interventions
- ❌ Historical BLs / weighing tickets / rotations
- ❌ Historical HSE incidents

## 10. Rollback plan

If T-0 data load fails irrecoverably (e.g., bad CSV mapping discovered mid-import, partial commits, or production data corruption detected):

1. **Halt imports immediately.** Do not run further `import-csv.ts` invocations.
2. **Truncate tenant rows** (run in dependency-safe order — children first):
   ```sql
   -- All commands scoped by tenant_id — RLS will refuse to delete other tenants' rows
   DELETE FROM equipment WHERE tenant_id = '{tenant_uuid}';
   DELETE FROM app_user   WHERE tenant_id = '{tenant_uuid}';
   DELETE FROM supplier   WHERE tenant_id = '{tenant_uuid}';
   DELETE FROM site       WHERE tenant_id = '{tenant_uuid}';
   ```
3. **Disable Keycloak group temporarily** so half-provisioned users cannot log in:
   ```bash
   curl -X PUT "$KEYCLOAK_URL/admin/realms/gravel-prod/groups/{group_id}" \
     -H "Authorization: Bearer $ADMIN_TOKEN" \
     -d '{"attributes":{"disabled":["true"]}}'
   ```
4. **Re-run T-0** with corrected CSVs (start from §5.2).
5. **Document root cause** in `.planning/cutovers/{customer}/rollback-{YYYYMMDD}.md` and link from the main cutover file.

Maximum rollback time budget: **2 hours from halt to re-import start**. If exceeded, escalate to SRE + customer comms.
